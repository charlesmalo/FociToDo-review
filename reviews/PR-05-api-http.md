**Already resolved / clarified during per-task review (not re-litigated, recorded as Accept/Fix below from pre-merge triage):**
- `app.set('etag', false)` is not directly asserted by a dedicated test (it's implicitly exercised — every `ETag` assertion in `todoRoutes.int.test.ts` would fail if Express's own weak hash-ETag won instead — but no test asserts the setting itself or that a weak ETag is absent).

- `server.ts`'s `shutdown()` is registered for both `SIGTERM` and `SIGINT` with no re-entrancy guard: a second signal re-invokes `shutdown()`, which calls `server.close()` a second time (errors as "not running") and `runtime.close()` (`pool.end()`) a second time; `pg.Pool.end()` rejects on a pool already ended, hitting the `catch` branch and calling `process.exit(1)` — so a double signal (not unusual with some process supervisors, or `Ctrl-C` pressed twice) turns a clean shutdown into a reported failure exit code.
- `errorHandler.ts` has a type-only `import type {} from 'pino-http'` solely to bring the `req.log` ambient augmentation into scope, independent of whether `pino-http`'s value import happens to also be in this compilation unit — a slightly unusual but explicitly-commented and intentional pattern (pre-approved during per-task review).
